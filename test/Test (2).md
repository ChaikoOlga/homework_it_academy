**1.** Назовите четыре принципа ООП. Как инкапсуляция помогает сохранять объект в корректном состоянии? Для чего проекту нужны пространства имён?
Инкапсуляция — скрывает внутреннее устройство объекта и позволяет работать с ним только через специальные методы.
Наследование — дает возможность создавать новый класс на основе уже существующего и использовать его свойства и методы.
Полиморфизм — позволяет использовать один и тот же метод для разных объектов, при этом каждый объект выполняет его по-своему.
Абстракция — оставляет только самые важные характеристики объекта и скрывает лишние детали.
Инкапсуляция не позволяет изменять данные объекта напрямую. Все изменения проходят через методы, которые могут проверить, правильные ли значения передаются. Благодаря этому объект не окажется в неправильном или недопустимом состоянии.

**2.** Что описывает интерфейс? Зачем делать интерфейсы небольшими? Может ли класс реализовать несколько интерфейсов и когда нужна явная реализация?
Интерфейс описывает, какие действия должен выполнять класс, но не объясняет, как именно они реализованы. Он задает набор методов и свойств, которые класс обязан реализовать.
Интерфейсы делают небольшими, чтобы каждый из них отвечал только за одну задачу.
Может. Это удобно, когда один класс должен выполнять несколько разных функций.

**3.** Распишите - solid, kiss, dry, yagni - своими словами
solid — это набор принципов, которые помогают писать понятный, гибкий и удобный для поддержки код.
kiss - этот принцип говорит, что код нужно делать как можно проще. Не стоит усложнять решение, если задачу можно решить понятным и легким способом.
dry - не нужно дублировать один и тот же код в разных местах.
yagni - не стоит писать функциональность «на будущее».

**4.** Что считается исключительной ситуацией? Когда выбрать `ArgumentException`, а когда спроектировать собственный тип исключения?
Исключительная ситуация — это ошибка или неожиданное событие, из-за которого программа не может продолжить работу в обычном режиме.
ArgumentException используют, когда проблема связана с неправильными аргументами, которые передали в метод.
Собственное исключение создают тогда, когда возникает особая ошибка, связанная с логикой именно вашего приложения, и стандартные исключения не подходят.

**5.** Для чего нужны `try`, несколько `catch` и `finally`? Чем `throw;` отличается от `throw ex;`?
try — это блок, в котором может возникнуть ошибка.
catch — перехватывает и обрабатывает исключение. Несколько catch нужны, чтобы по-разному обрабатывать разные типы ошибок.
finally — выполняется всегда, независимо от того, была ошибка или нет. Обычно в нем освобождают ресурсы и выполняют завершающие действия.
throw; — повторно выбрасывает текущее исключение и сохраняет информацию о месте, где оно возникло.
throw ex; — тоже выбрасывает исключение, но сбрасывает информацию о первоначальном месте возникновения ошибки, из-за чего ее сложнее найти.

**6.** Когда достаточно `File.ReadAllTextAsync`, а когда нужен `FileStream`? Зачем нужен `using`?
File.ReadAllTextAsync используют, когда нужно быстро прочитать весь файл целиком и он не слишком большой.
FileStream нужен, когда файл большой, его нужно читать или записывать по частям, либо требуется более гибкая работа с файлом.
using нужен, чтобы после завершения работы автоматически освободить ресурсы и закрыть файл.

**7.** Что такое сериализация и десериализация?
сериализация — это процесс преобразования объекта в формат, который можно сохранить в файл, передать по сети или записать в базу данных.
десериализация — это обратный процесс, при котором сохраненные данные снова преобразуются в объект, с которым можно работать в программе.

**8.** Что хранит делегат?
Ссылку на один или несколько методов с определенной сигнатурой.

**9.** Когда выбирать `Action`, а когда `Func`?
Action используют, когда метод ничего не возвращает, а только выполняет какое-то действие.
Func используют, когда метод возвращает результат.

**10.** Зачем нужен LINQ? Чем method syntax отличается от query syntax? Что такое отложенное выполнение и в какой момент выполняется `Where(...).Select(...)`?
LINQ нужен для удобной работы с коллекциями данных: позволяет искать, фильтровать, сортировать и преобразовывать данные с помощью единого синтаксиса.
method syntax — это запись с использованием методов (Where, Select и других).
query syntax — это запись, похожая на SQL, с ключевыми словами from, where, select.
отложенное выполнение означает, что запрос не выполняется сразу после написания.

**11.** Как GC определяет, что объект можно удалить? Для чего нужны поколения 0, 1 и 2?
GC удаляет объект, если на него больше нет ссылок и программа не может к нему обратиться.
0— новые объекты, которые чаще всего быстро удаляются.
1— объекты, пережившие одну сборку мусора.
2— объекты, которые существуют долго и проверяются реже, что повышает производительность программы.

**12.** Когда вызывается финализатор и почему на него нельзя рассчитывать для своевременного закрытия файла? Что решает паттерн `Dispose`? Что такое `GC.Collect()`?
Финализатор вызывается сборщиком мусора перед удалением объекта, но точное время его вызова неизвестно. Поэтому нельзя рассчитывать на него для своевременного закрытия файла или освобождения других ресурсов.
Dispose позволяет освободить ресурсы сразу, как только они больше не нужны, не дожидаясь работы сборщика мусора.
GC.Collect() — это метод, который принудительно запускает сборщик мусора.

**13.** Чем параллельность отличается от асинхронности?
параллельность - одновременно выполнять, а асинхронность - не ждать без дела.

**14.** Для чего применяют `lock`? Назовите опасность нескольких блокировок.
Чтобы только один поток одновременно мог работать с общими данными. 
Опасность нескольких блокировок — возникновение взаимной блокировки, когда два или больше потоков ждут освобождения ресурсов друг другом и программа перестает выполняться.

**15.** Для чего нужен `Task.WhenAll`?
Чтобы дождаться завершения сразу нескольких асинхронных задач.

**16.** Что делает `await`, пока операция не завершена? Для чего передают `CancellationToken`?
Не блокирует поток во время ожидания. Пока операция не завершена, поток может выполнять другие задачи, а после завершения выполнение метода продолжается.
CancellationToken передают, чтобы при необходимости можно было отменить выполнение длительной или ненужной операции.

**17.** В чём разница между отладкой и профилированием? Какой инструмент выбрать, если программа: а) падает; б) медленно работает; в) постоянно увеличивает потребление памяти?
Отладка — это поиск и исправление ошибок в программе.
Профилирование — это анализ работы программы, чтобы найти причины медленной работы или большого расхода ресурсов.

**18.** Что такое метаданные типа и как получить `Type`? Для чего нужны `PropertyInfo`, `MethodInfo`, `Activator.CreateInstance` и `BindingFlags`? Что делает атрибут и почему сам по себе он не выполняет проверку?
Метаданные типа — это информация о классе: его свойства, методы, поля, конструкторы и другие сведения.
Type получают с помощью typeof, метода GetType() или по имени типа.
PropertyInfo нужен для получения информации о свойствах и работы с ними.
MethodInfo используется для получения информации о методах и их вызова.
Activator.CreateInstance позволяет создать объект по его типу во время выполнения программы.

BindingFlags задает, какие именно члены типа нужно искать, например публичные, приватные, статические или нестатические.

**19.** Какой метод будет вызван и что выведет программа и почему так?

```csharp
class Delivery
{
    public virtual decimal Cost(decimal weight) => weight * 2m;
}

class ExpressDelivery : Delivery
{
    public override decimal Cost(decimal weight) => base.Cost(weight) + 5m;
}

Delivery delivery = new ExpressDelivery();
Console.WriteLine(delivery.Cost(3m));
```

---
Будет вызван метод Cost из класса ExpressDelivery, потому что он переопределяет (override) виртуальный метод базового класса.

## Часть II — Практика (консоль)

**Одно приложение** — `dotnet new console` (`.NET 10`). Все блоки ниже — части одного проекта, не отдельные программы. Код должен собираться, не падать на ожидаемых ошибках ввода и быть читаемым.

### Общая схема

1. При запуске создать каталог с несколькими товарами.
2. Главное меню — `do-while` + `switch`, пункты **1–3** вызывают соответствующий блок.
3. Ввод чисел — через `TryParse`; ожидаемые ошибки обрабатываются без завершения приложения.
4. Для async-операций использовать `async Main`, `Task` и `await`.

---

### Блок 1. Каталог — ООП, интерфейсы и исключения

- абстрактный `Product`: `Sku`, `Name`, `Price`, защищённый конструктор и метод изменения цены с проверкой;
- два наследника: `PhysicalProduct` и `DigitalProduct`;
- абстрактный метод расчёта стоимости доставки;
- интерфейс `IIdentifiable` с идентификатором товара;
- полиморфная коллекция `List<Product>`;
- собственное исключение `DuplicateSkuException` при добавлении товара с повторяющимся SKU.

**В меню:** добавить физический или цифровой товар либо показать каталог и стоимость доставки.

---

### Блок 2. LINQ-отчёт

Отчёт должен:

- отфильтровать товары по введённой минимальной цене через `Where`;
- сгруппировать товары по фактическому типу;
- для каждой группы посчитать количество и среднюю цену;
- отсортировать группы по средней цене по убыванию;
- получить самый дорогой товар через `MaxBy`;
- материализовать итоговый список через `ToList`;
- одну выборку записать method syntax, вторую — query syntax.

**В меню:** запросить минимальную цену и вывести отчёт.

---

### Блок 3. Асинхронное обновление цен

Сервис получает коллекцию товаров и асинхронно имитирует получение новых цен:

- для каждого товара создаётся `Task`;
- все операции ожидаются через `Task.WhenAll`;
- метод принимает `CancellationToken`;
- ожидаемая отмена обрабатывается отдельно от остальных исключений;
- не использовать `.Result`, `.Wait()` и `async void`.

**В меню:** обновить цены всех товаров на 10%, вывести результат по SKU и идентификатор текущего managed-потока.
